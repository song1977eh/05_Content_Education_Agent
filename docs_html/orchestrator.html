오케스트레이터 — 폴더 단위 상태값 (orchestrator.md)

관리 단위: 폴더 1개(= 답사/전시/세미나/워크숍 1건) = 1 레코드. 파일 단위로 쪼개지 않는다. 실제 상태는 data/state.json에 영속 저장한다. 이 문서는 상태값 스키마와 전이 규칙을 정의한다.

상태 전이도

미분석
  → 분석중(일괄)
      → 승인대기 (마스킹·출처·저작권 중 하나라도 결측/불명확)
          → [사람 승인] → 분석완료
          → [승인 보류] → 승인대기 유지 (다음 단계로 진행하지 않음)
      → 분석완료 (결측 없음)
  → 재사용노트작성중 → 재사용노트완료
  → 콘텐츠초안중(유형: 실무 | 강의 | 판매 | 해민건축 — 동시에 여러 유형 가능)
      → 초안완료(검수대기)
          → 검수완료
          → 반려 → 콘텐츠초안중으로 복귀

역행 가능: 검수 단계에서 반려되면 해당 콘텐츠 유형만 콘텐츠초안중으로 되돌아간다(폴더 전체 재분석은 필요 없음).

data/state.json 스키마

{
  "folders": {
    "2026-09-15_답사_판교테크노밸리": {
      "type": "답사",
      "date": "2026-09-15",
      "status": "분석완료",
      "approval_log": [],
      "content_drafts": {
        "실무활용자료": "초안완료(검수대기)",
        "강의자료": null,
        "판매콘텐츠": null,
        "해민건축콘텐츠": null
      },
      "last_updated": "2026-09-17"
    }
  }
}
  • status: 미분석 / 분석중 / 승인대기 / 분석완료 / 재사용노트작성중 / 재사용노트완료
  • content_drafts.[유형]: null(미착수) / 콘텐츠초안중 / 초안완료(검수대기) / 검수완료 / 반려
  • approval_log: 승인대기가 발생했을 경우 source_register.md와 동일한 형식으로 기록

모듈 ↔ 상태 매핑

모듈 참조 문서 상태 전이
1. 수집 rawsource_taxonomy.md (없음) → 미분석
2. 마스킹 검증 privacy_masking_checklist.md 미분석 → 분석중 → (승인대기 | 분석완료로 직행)
3. 분해·추출 content_principles.md §4 분석중 → 분석완료
4. 재사용노트 작성 — 분석완료 → 재사용노트작성중 → 재사용노트완료
5. 콘텐츠 유형 매핑·초안화 content_conversion_rules.md 재사용노트완료 → 콘텐츠초안중 → 초안완료(검수대기)
6. 검수 대기·배포 연계 — 초안완료(검수대기) → 검수완료 / 반려

세션 간 이어받기 규칙

새 세션(집/사무실)을 열면, data/state.json을 먼저 읽어 분석중/승인대기/콘텐츠초안중 상태인 폴더가 있는지 확인하고 이어서 진행한다. 상태값 없이 대화 맥락에만 의존하지 않는다.
